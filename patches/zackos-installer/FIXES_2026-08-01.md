# Installer fixes (2026-08-01 session, post-revert reconstruction)

1. **install_bootloader**: bare `grub-install` -> "command not found" in the
   live env (GRUB is Nix-provided via /usr/local/sbin symlink, but that dir
   isn't guaranteed on $PATH for every shell context). Fixed to use
   `shutil.which` with an explicit `/usr/local/sbin/grub-install` fallback.

2. **check_disk_space**: `du -sx` (one-file-system) on this live overlayfs
   root undercounts to ~0G needed, because unmodified files are backed by
   the lower (squashfs) device and copied-up files by the upper (tmpfs)
   device - they don't share one st_dev. Fixed to use plain `du -s` (no -x),
   relying on the existing excludes list instead (proc/sys/dev/tmp/run/mnt/media).

3. **Networking never comes up automatically**: no dhcp client was ever
   invoked in `/etc/rc.d/init.d/network` (only static
   /etc/sysconfig/ifconfig.* files, which never existed), so `nix-env`
   installs during `install_wm`/`install_init` (inside chroot, sharing the
   live system's network namespace) had no route out. Fixed: `network`
   init script now auto-detects any non-lo interface and runs
   `/usr/local/sbin/dhcpcd -b <iface>` on it if no static config exists.
   `dhcpcd` (via `nix-env -iA nixpkgs.dhcpcd`) is now baked into the live
   rootfs and symlinked to /usr/local/sbin.

4. **`/etc/profile` never sourced `/etc/profile.d/*.sh`**, so
   `/etc/profile.d/nix.sh`'s PATH (Nix profile bins) was never actually
   applied for a plain login shell - this is why earlier steps needed
   manual `export PATH=...` prefixes. Fixed `/etc/profile` to loop-source
   `/etc/profile.d/*.sh`.

5. **`/usr/local/bin/zackos-install` dispatcher** now explicitly exports
   PATH (nix profile dirs + /usr/local/sbin) before exec'ing python3, so the
   installer's own subprocess calls (grub-install, dhcpcd, nix-env, etc.)
   are always reachable regardless of how the dispatcher was invoked.

6. **Sandbox DNS gotcha (dev-environment only, not a ZackOS bug)**: this
   sandbox's /etc/resolv.conf has a required local resolver
   `nameserver 172.21.0.1` (a "modal resolver") FIRST, with 1.1.1.1/8.8.8.8
   as fallback. Overwriting a chroot's resolv.conf with only `8.8.8.8` broke
   DNS resolution entirely inside that chroot (outbound DNS to public
   resolvers appears blocked/unreliable here) - always copy the host's full
   resolv.conf verbatim into any chroot needing network access in this dev
   sandbox.

grub2 (2.12) and dhcpcd (10.3.2) are pre-installed into the live rootfs's
Nix store and symlinked at /usr/local/sbin/{grub-install,grub-mkconfig,
grub-mkrescue,dhcpcd} - confirmed working via `--version` inside chroot.
